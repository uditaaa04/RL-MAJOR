These datasets of synthetic task flow graphs were generated to evaluate the performance and scalability of an optimal task allocation approach for applications of various structures and sizes in an environment following the edge/hub/cloud paradigm. The system under study comprised an edge device (e.g., a single-board computer attached to an unmanned aerial vehicle (UAV)) interacting with a hub device (e.g., a laptop), which in turn communicated with a more computationally capable cloud server. The objective was the minimization of either overall latency or overall energy consumption, under memory, storage, energy, and task precedence constraints. We considered that a percentage of the tasks required fixed allocation on the edge or hub device.

We generated 18 task flow graphs of parallel, serial, and mixed (a combination of parallel and serial) structure with 10, 100, and 1000 nodes, and various in/out degrees, utilizing the Task Graphs For Free (TGFF) random task graph generator [1],[2] with the following input (#Nodes, Max In/Out Degree):

 P1.2   10        2/2                  Parallel task flow graph with 10 nodes (variant 2)     P1_2.xlsx
 P2.1   100       2/3                  Parallel task flow graph with 100 nodes (variant 1)    P2_1.xlsx
 P2.2   100       5/3                  Parallel task flow graph with 100 nodes (variant 2)    P2_2.xlsx

 S2.1   100       2/2                  Serial task flow graph with 100 nodes (variant 1)      S2_1.xlsx

Each file includes the following fields. The first two fields were generated by TGFF, whereas the rest were added post-generation, using representative random values: 

[SN]  [Field]                         [Description]
 1     TaskID                          ID of task
 2     ParentTasks                     List of direct predecessor tasks (0=none)
 3     LatencyEdge1 (ms)               Execution time on edge device 1
 4     LatencyEdge2 (ms)               Execution time on edge device 2
 5     LatencyEdge3 (ms)               Execution time on edge device 3
 6     LatencyHub (ms)                 Execution time on hub device
 7     LatencyCloud (ms)               Execution time on cloud server
 8     PowerEdge1 (W)                  Power consumption on edge device 1
 9     PowerEdge2 (W)                  Power consumption on edge device 2
 10    PowerEdge3 (W)                  Power consumption on edge device 3
 11    PowerHub (W)                    Power consumption on hub device
 12    PowerCloud (W)                  Power consumption on cloud server
 13    Memory (Mbit)                   Required main memory
 14    Storage (Mbit)                  Required storage
 15    OutputData (Mbit)               Output data size
 16    FixedAllocation (0=no,1=e,2=h)  Requires fixed allocation on edge device (1), hub device (2), or not (0)

Parameter Values:
(a) LatencyEdge1, PowerEdge1, Memory, Storage, and OutputData were selected randomly from measurements obtained through profiling the performance and power consumption of a relevant real-world application [3] executed on the reference device (edge device 1 - Raspberry Pi 3 Model B).
(b) LatencyEdge2 and PowerEdge2 were based on the performance ratio of edge device 2 (Odroid XU4) with respect to the reference device, and LatencyEdge1 and PowerEdge1, respectively.
(c) LatencyEdge3 and PowerEdge3 were based on the performance ratio of edge device 3 (Jetson TX2) with respect to the reference device, and LatencyEdge1 and PowerEdge1, respectively.
(d) LatencyHub and PowerHub were based on the performance ratio of hub device (Mi Notebook Pro) with respect to the reference device, and LatencyEdge1 and PowerEdge1, respectively.
(e) LatencyCloud and PowerCloud were based on the performance ratio of cloud server (HPE ProLiant DL580 Gen10) with respect to the reference device, and LatencyEdge1 and PowerEdge1, respectively.
    The performance ratio in (b)-(e) was calculated by running the benchmarks in [4]-[6] on all five devices.
(f) FixedAllocation was determined based on the following percentages of tasks per task flow graph requiring fixed allocaton on the edge (e) or hub (h) device:
     - P1.1: e=5%,    h=2% 
     - P1.2: e=4%,    h=2%
     - P2.1: e=4%,    h=2%
     - P2.2: e=3%,    h=1%
     - P3.1: e=5%,    h=2%
     - P3.2: e=4%,    h=2%
     - S1.1: e=4%,    h=2%
     - S1.2: e=4%,    h=3%
     - S2.1: e=4%,    h=3%
     - S2.2: e=1%,    h=3%
     - S3.1: e=5%,    h=3%
     - S3.2: e=2%,    h=2%
     - M1.1: e=4%,    h=1%
     - M1.2: e=1%,    h=2%
     - M2.1: e=1%,    h=3%
     - M2.2: e=2%,    h=2%
     - M3.1: e=4.8%,  h=2%
     - M3.2: e=1.86%, h=1%
